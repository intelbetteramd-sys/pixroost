# 0005. Передача по локальной сети: HTTPS с пиннингом и докачкой

- Статус: Принято; подтверждено спайками S-03 и S-04 на Android и Windows, проверка на iPhone ждёт Mac (Фаза 1)
- Дата: 2026-09-24

## Контекст

Телефон отправляет на ПК тысячи файлов по 2–200 МБ. Связь может рваться (телефон уснул, ушёл из сети).
На iOS загрузки желательно продолжать в фоне. Канал должен быть защищён от чужих устройств в сети.

## Решение

- ПК поднимает **HTTPS-сервер** (Ktor Server на JVM) с самоподписанным сертификатом на ключе устройства.
- Телефон **пиннит** отпечаток сертификата, полученный из QR при сопряжении.
- Аутентификация телефона — подпись nonce ключом устройства → короткоживущий токен сессии.
- Загрузка файлов — **с докачкой** в духе протокола tus. Идентификатор загрузки — SHA-256 файла: `POST`
  отвечает смещением, `PATCH` досылает остаток с `Upload-Offset`, ПК проверяет SHA-256 (спайк S-03).
- Дедупликация на приёме: если SHA-256 уже есть в архиве — передача пропускается.
- Обнаружение — mDNS `_pixroost._tcp` для прямого пути; для развёрнутого подключения (запасной путь без правила
  брандмауэра) ПК рассылает UDP-запрос «кто тут?» ([спайк S-04](https://github.com/intelbetteramd-sys/pixroost/issues/23)).
- Правило брандмауэра Windows для всех сетей, включая общедоступные, ставит установщик
  (проверено в [спайке S-07](https://github.com/intelbetteramd-sys/pixroost/issues/27): MSIX и `.exe` на Windows 11).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| WebRTC data channels | сложная сигнализация, тяжёлые нативные библиотеки; оправдан для интернета, не для LAN |
| Noise-протокол поверх TCP | хорошая криптография, но нет готовой KMP-библиотеки; TLS даёт то же с готовыми инструментами |
| SMB / WebDAV-сервер на ПК | неудобно настраивать, нет пиннинга, сложно с докачкой |
| iroh (QUIC) | рассматриваем для v1.1 (интернет); для LAN избыточен |

## Последствия

- ➕ Стандартные инструменты (Ktor client/server), легко отлаживать.
- ➕ Background `URLSession` на iOS может продолжать загрузки, когда приложение свёрнуто.
- ➖ Не проверено, как background `URLSession` работает с пиннингом самоподписанного сертификата: проверка на iPhone ждёт Mac
  (трек Apple, [#37](https://github.com/intelbetteramd-sys/pixroost/issues/37)). Это единственный открытый вопрос решения.
- ➖ ПК принимает входящие соединения, в том числе в общедоступных сетях: Windows 11 часто так помечает и
  домашнюю сеть. Правило ставит установщик, окон брандмауэра пользователь не видит, у `.exe` и `.msi` — запрос прав
  администратора при установке. Внутрь пускают только сопряжённые устройства. Развёрнутое подключение без
  правила проверено спайками S-04 и S-03 и остаётся в запасе
  ([путь соединения](../devices-and-transfer.md#путь-соединения)).
- ➖ С VPN и в гостевой сети с изоляцией устройств прямой путь не работает; для них — ретранслятор в v1.1.
- ➖ Системный запрос доступа к локальной сети на телефоне — отдельный шаг в первом запуске.

## Итоги спайка

Решение подтверждено, менять ADR не нужно. Стенд: Windows 11 и Redmi Note 9 (Android 12), оба по Wi-Fi 5 ГГц.
Подробности и таблицы — в [devices-and-transfer.md](../devices-and-transfer.md#что-показал-спайк-s-03).

**S-03, передача на ПК** ([#24](https://github.com/intelbetteramd-sys/pixroost/issues/24)):

- Ktor Server (Netty) с самоподписанным сертификатом ECDSA P-256 (BouncyCastle) и Ktor Client на OkHttp с пиннингом
  отпечатка работают как задумано.
- Докачка в духе tus проверена на обоих путях: после обрыва Wi-Fi посреди видео телефон узнаёт у ПК смещение и досылает
  остаток; SHA-256 совпал у всех 21 файла (20 фото по 3 МБ и видео 500 МБ).
- Скорость: фото 4,2 МБ/с, видео 4,7 МБ/с на прямом пути; 3,5 и 4,2 МБ/с на развёрнутом. Оба устройства на Wi-Fi, поэтому
  каждый байт проходит по воздуху дважды; критерий ≥ 20 МБ/с в этой сети не проверить. Скорость нужно перемерить с ПК по кабелю
  и на современных устройствах.
- Правило брандмауэра только для частных сетей не сработало: Windows 11 пометила домашнюю сеть как общедоступную,
  телефон получал таймаут. Правило должно быть для всех профилей, это уже записано в решении.

**S-04, поиск ПК** ([#23](https://github.com/intelbetteramd-sys/pixroost/issues/23)):

- С правилом телефон находит ПК по mDNS за 0,4 с и подключается за 38 мс. Без правила Windows молча отбрасывает входящие
  пакеты: прямой путь не работает, mDNS на ПК даёт только запись из кэша.
- Развёрнутое подключение работает без правила: ПК находит телефон рассылкой за ≈ 1 с и подключается сам. Остаётся в
  запасе, в v1.0 не используется: основной путь нужен прямой, потому что только он позволяет iPhone отправлять в фоне.
- С VPN не работает ни один путь; приложение подсказывает выключить VPN.

**Не проверено:**

- iPhone: фоновая `URLSession` с пиннингом, Bonjour и запрос доступа к локальной сети (ждёт Mac, трек Apple). Если
  фоновая отправка с пиннингом не заработает, пересматриваем только iOS-часть, решение для Android и ПК остаётся.
- Общедоступная сеть и Windows 10 для развёрнутого пути, гостевая сеть с изоляцией клиентов.
